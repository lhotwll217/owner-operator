# Set up pstack model routing

Inspect the existing owner-controlled harness, model, and effort policy. In Owner Operator, read its bundled `select-harness-for-delegation` skill and use its capability discovery only when available. In other coding harnesses, inspect the models and reasoning choices actually exposed. Report which workflow roles can run and which cannot.

The roles are implementation, hard implementation, judgment/prose, how explorer/explainer, why investigator/synthesizer, reflect tooling/judgment/divergent/synthesizer, arena runners/cross-judge, swarm workers, architect runners, and interrogate reviewers. Panel cardinality determines the number of perspectives; unsupported diversity remains a stated gap.

Preserve every owner-supplied identity field. This port defines no default model roster and creates no always-applied rule or second preference registry. Propose changes through the existing owner policy only when explicitly requested; apply them only with the approval that policy requires. Parent inheritance is available only where the harness supports it and the owner policy permits it.

Report available and unavailable roles and any reload requirements. If the project lacks a verification harness, offer [create verification](../pstack-create-verification-skill/WORKFLOW.md) once; run it only when requested.
